# 选择用户页键盘布局修复设计

## 问题

选择用户页打开“添加用户”弹窗后，输入框获取焦点会弹出软键盘。弹窗自己的 `Scaffold` 已设置 `resizeToAvoidBottomInset: false`，但弹窗下方的选择用户页仍使用 `AppHeaderPage` 的默认键盘避让行为。因此底层页面高度随键盘缩小，固定尺寸内容被向上挤压并产生约 284 像素的布局溢出。

## 期望行为

软键盘弹出和收起时：

- 选择用户页保持原始尺寸和位置；
- 添加用户弹窗保持原始尺寸和位置；
- 键盘可以覆盖弹窗下方内容；
- 其他使用 `AppHeaderPage` 的页面行为不变。

## 设计

在 `ChoseUsersPage` 创建 `AppHeaderPage` 时显式传入 `resizeToAvoidBottomInset: false`。不修改公共组件默认值，也不重写弹窗路由的 `MediaQuery`。

该设置让底层页面的 `Scaffold` 忽略键盘产生的底部 inset。弹窗已经使用相同设置，因此两个路由都不会因键盘出现而重新压缩布局。

## 测试与验证

- 添加针对选择用户页根布局的组件测试，验证它明确关闭 `Scaffold.resizeToAvoidBottomInset`；测试应在生产代码修改前失败、修改后通过。
- 运行相关 Flutter 测试。
- 运行目标文件格式化和静态分析，确认没有引入新的诊断。

## 范围

仅修改选择用户页的键盘避让配置及对应测试。不调整弹窗尺寸、字段位置、键盘类型、公共页面默认行为或其他现有改动。
