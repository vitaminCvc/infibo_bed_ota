# 升降杆状态同步

用户已授权修复首页和启动页，并确认 0x0011 与 0x0010 使用相同枚举：0 停止，1 手动上升，2 手动下降，3 一键上升，4 一键下降。

用户通过截图补充说明 0x0011=3、0x0010=4 仍不符合要求，并明确确认：App 要主动向 0x0010 写入 3，使控制寄存器、状态寄存器和 UI 三者一致。这取代第一轮仅更新 UI、不回写控制寄存器的范围。

两页共用 JoystickControl，因此在共用组件中修复。显示期间每 500ms 读取 0x0011，即使当前空闲也继续检测；按返回状态选择已有图片。随后读取 0x0010，不相等时写入状态值，相等不重复写。保留点击操作的即时反馈和手动操作的 1 秒防抖、松手停止。

页面被覆盖时暂停轮询，返回后恢复。忽略未知值、失败读数和已过期响应；失败后继续读取。松手处理以本地实际按压记录为准，不能依赖可能被状态反馈改变的图片。

共享总线记录本地命令代次及在途写入，首页离开停止、启动页升降顺序和摇杆操作均接入，防止校正读数跨越新命令。按压期间由手势控制，不自动回写覆盖；主动停止后，在收到停止反馈之前不将旧运动状态写回，避免重新启动。状态读取成功但控制寄存器读取或写入失败时，UI 仍按实际状态更新，后续周期重试校正。

选择共用组件修复，避免两页独立实现导致行为分歧；不改页面布局，不改变启动治疗的到位判定规则。
